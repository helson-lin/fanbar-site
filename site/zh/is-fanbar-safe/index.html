FanBar 安全吗？ 它能碰什么，这里写清楚。

安全。在你开启手动控制之前，FanBar 只读取传感器。开启之后，一个开源的小型 Helper 只在每个风扇的硬件上下限之内设置目标转速，不做其他任何事。每个版本都经过 Apple 公证，所有说法你都可以亲自核实。

已对照源码核实于 2026 年 10 月 15 日亲自验证
FanBar 由我们维护，所以请把本页当作我们的说法，然后去核实。每条说法都链接到对应的源码文件，下面的命令可以直接在你的 Mac 上运行。

大家最先问的四个问题

会损坏风扇吗？

不会。目标转速始终在风扇向 macOS 报告的最低与最高转速之间。

root Helper 做什么？

读取风扇、设置有上下限的目标值、把控制权交还 macOS，仅此而已。

能看源码吗？

能。App 和 Helper 都以 GPL-3.0 开源在 GitHub，Helper 约 700 行。

经过公证吗？

是。每个版本都使用 Developer ID 签名并经过 Apple 公证。

FanBar 会损坏风扇或让 Mac 过热吗？

手动风扇控制本身并非没有风险，所以 FanBar 的设计是始终停留在 Mac 自己定义的范围之内。

转速始终在硬件范围内

写入前，Helper 会读取每个风扇报告的最低和最高转速，并把所有目标值限制在这个范围内。唯一的例外是有意为之：温度曲线最低温的一段可以请求 0 RPM 静止，这和 Apple Silicon Mac 在温度较低时自己的做法一致。

不改动 macOS 的过热保护

FanBar 只写入风扇模式和目标转速。macOS 的降频和硬件的临界温度关机机制都不受影响，无论风扇设成什么都照常工作。

在 root 边界拒绝异常输入

即使请求来自被篡改的客户端，Helper 也会拒绝负数或非有限的转速值，以及超出 0–100% 的曲线比例。

可选的高温提醒

CPU 或 GPU 达到 90 °C 时，FanBar 可以发送通知，避免过于安静的设置被忽视。

以下情况 FanBar 会把控制权交还 macOS：

  • 你选择「自动」，或定时预设到期（15 分钟、30 分钟或 1 小时）
  • 你退出 FanBar，或最后一个连接 Helper 的 App 断开
  • Helper 正在退出
  • 多风扇写入中任意一个失败——整机回滚，绝不停留在一半设置的状态

长时间全速运行主要带来噪音和额外磨损。日常使用建议选择「自动」或温度曲线。

Helper 能做什么，不能做什么

在 macOS 上修改风扇转速需要以 root 身份访问 AppleSMC；读取温度则不需要。所以只有在你开启手动控制并在 macOS 中批准后，才会安装 Helper。

Helper 可以

  • 读取风扇数量、当前转速，以及每个风扇的最低和最高转速
  • 设置目标转速、预设或曲线比例——都会限制在风扇范围之内
  • 恢复 macOS 自动风扇控制

Helper 不能

  • 写入任意 SMC 键——接口中没有通用写入
  • 执行命令、读取文件或访问网络——这些功能的代码根本不存在
  • 接受其他 App 的指令——只接受与 FanBar 同一 Apple 开发者团队签名的客户端
  • 在 FanBar 断开后继续保持手动控制

不必只听我们说

三项检查，几分钟就能完成，无需信任本页。

  1. 1. 确认 Apple 公证

    安装后在终端运行以下命令，macOS 应显示这是经过公证的 Developer ID 版本。

    $ spctl -a -vv /Applications/FanBar.app/Applications/FanBar.app: accepted
source=Notarized Developer ID
origin=Developer ID Application: JiangLin He (64S5F787T9)

  2. 2. 阅读以 root 运行的代码

    整个特权部分只有两个短文件。重点看客户端签名校验、输入检查和范围限制。

    • FanBarHelperService.swift
    • SMCFanDriver.swift
    • FanCoolingTarget.swift

  3. 3. 检查 App 的网络请求

    FanBar App 没有账号、广告或统计。它每天通过 Sparkle 向 GitHub Releases 检查一次更新，每个更新都必须通过 Apple 公证和 FanBar 自己的 EdDSA 签名校验。兼容性报告只有在你查看并确认后才会发送。

如何关闭或移除

交还 macOS 控制

在菜单栏弹窗中选择「自动」，Helper 会立即停止控制风扇。

停用 Helper

macOS 13 及以上：打开「系统设置 → 通用 → 登录项与扩展」，在「允许在后台」中关闭 FanBar。

完全卸载

先退出 FanBar。通过 Homebrew 安装的，以下命令会同时卸载 Helper，并删除偏好设置和缓存。

brew uninstall --cask --zap helson-lin/fanbar/fanbar

关于安全，直接回答

FanBar 安全吗？

安全。默认情况下 FanBar 只读取温度和风扇转速，散热由 macOS 管理。手动控制需要你明确批准一个签名 Helper，它只能在每个风扇的硬件范围内设置目标转速。FanBar 以 GPL-3.0 开源，每个版本都经过 Apple 公证。

FanBar 会损坏 Mac 的风扇吗？

FanBar 会把所有目标值限制在每个风扇报告的最低和最高转速之间，无法让风扇超出额定范围。唯一的例外是温度曲线最低温一段有意设置的 0 RPM 静止，这和 Apple Silicon Mac 自己的做法一致。长时间全速运行主要带来噪音和额外磨损。

风扇设错了会让 Mac 过热吗？

FanBar 不改动 macOS 的散热管理。温度升高时，无论风扇目标是多少，macOS 仍会降频，硬件仍会在临界温度时关机。FanBar 还可以在 CPU 或 GPU 达到 90 °C 时通知你。

为什么 FanBar 需要管理员批准？

macOS 只允许 root 进程通过 AppleSMC 修改风扇转速。只有在你开启手动控制时 FanBar 才会请求批准，监控功能不需要。Helper 仅限于读取风扇、设置有上下限的目标值和恢复自动控制。

FanBar 会收集我的数据吗？

不会。FanBar App 没有账号、统计或广告。唯一的网络活动是每天一次通过 Sparkle 向 GitHub Releases 检查更新，以及你主动选择发送、并经过你查看的兼容性报告，其中不含序列号等唯一标识。

FanBar 是病毒或恶意软件吗？

不是。FanBar 使用 Apple Developer ID 签名并经过 Apple 公证，完整源码（包括特权 Helper）公开在 GitHub，任何人都可以审计。
